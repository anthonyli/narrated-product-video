# 共享元素动画：制作与验收门禁

适用于选择「共享元素连续动画」的正式成片，尤其已存在用户认可参考片时。它不把录屏剪辑、用户明确要求的静态讲义或无声样片强行改成全程运动。本门禁验证制作过程与成片证据，不能保证用户一定喜欢。

## 1. 分镜先过关，再制作

在项目 `work/qa/` 记录每个关键解释段的：论点、对应口播、对象 ID、前态、变化、后态、变化解释了什么、预期触发词。跨场要说明同一对象怎样接上，不能只有“标题 + 三张卡片 + 淡入”。

- 至少选一条贯穿主要论点的对象变化链。复杂主题可能需要多条，不能为了达标硬凑运动数量。
- 状态必须有可见差别，如一份观察收拢成摘要、摘要进入新会话后展开为相关记录。单纯移动装饰圆点不算解释。
- 遮罩可以辅助接点，但“同一整屏 wipe 后换另一页”不是对象连续性的证据。
- 对金额、条件、长文字可以停稳阅读；预先写明阅读对象及语义原因。不要让所有信息一开始摆齐，再靠字幕变化撑完整段落。
- 沿用参考片时提取其对象重排、匹配迁移、聚焦和状态变化机制，不只采样颜色、字体和帧率。不要把参考片的特定品牌或七幕结构变成通用模板。

## 2. 短样片必须展示难点

先实渲约 6–12 秒，包含**一次有意义的对象状态变化和一个真实跨场接点**。仅做标题入场、纯静态拼图或单帧截图不能过关。

分别检查：前态→中间态→后态；接点前后及连续过程；内容是否被遮罩、字幕、安全区截断。对象形状、位置或视觉身份的接续应有解释，不能在遮挡中偷换为完全无关的新对象。保存短片、连续帧或接点帧证据和实际观察结论。发现问题先修改并重新渲染短片，再扩展全片。

短样片通过不代表正式片通过。正式声音可能把 4 秒段拉成 12 秒，产生新的长静止，必须重新按实际声音布置变化。

## 3. 正式片分开验收

使用 `assets/acceptance/record.template.json` 建立本项目验收记录。所有检查只能标为 `passed`、`failed`、`not_checked`，不得把尚未检查写成通过。

必须分别记录：

- `storyboard`：对象链与语义因果。
- `sample_visual`：真实短片连续运动和跨场接续。
- `final_visual`：最终成片逐段审查布局、连续动作、长停与全部主要接点。抽帧不能替代连续过程检查。
- `final_semantic`：正式时间轴的画面变化是否跟随当前口播；不得仅用段落字数均分伪装精确时间。
- `technical`：全片解码、尺寸、帧率、编码、时长和音画终点。
- 有旁白时 `audio_transcript`：全文 ASR 差异核对，实际漏句/重复/错词必须修复音频，不能只改字幕遮盖。
- 有字幕时 `captions`：最终版本的时间、换行、可读性、安全区与结尾。
- `audio_listening` 单列真人/可用审听检查。ASR 通过不能将其标为通过；无法审听时如实披露，可交付技术与识别已核验版，不宣称听感/音色已完全验收。实际已经发现的错读或中断属于阻塞项，不能用“未审听”豁免。

每个检查要有实际检查者标识（例如 `agent:reviewer`，不能冒称真人）、具体观察、项目相对证据路径及 SHA256。最终视频 SHA256 将记录绑定到确切文件；换字幕、换声音或重渲后必须重新核对受影响检查，并重新计算哈希。禁止拿旧版报告配新版视频。

## 4. 自动检测只找疑点，不替代视觉结论

```sh
python "$SKILL_DIR/scripts/scan_visual_holds.py" outputs/final.mp4 \
  --output work/qa/visual-holds.json
```

扫描以 2 fps 读取主画面灰度差，默认 ROI `[0, 0.12, 1, 0.82]` 排除常见顶部/字幕带。先检查实际构图，字幕位置不同时用 `--roi LEFT TOP RIGHT BOTTOM` 调整；不要为了减少警告把主要内容排除。默认连续 3 秒低变化产生待审查区间，**3 秒是排查阈值，不是禁止停稳的设计限制**。

对每个疑点填写 `hold_reviews`，用 `scan_span_index` 对应扫描数组下标，并保存时间区间的帧/视频证据：

- 确属合理阅读停稳：`decision=justified_reading`，写清读什么、为何需要这段时间及口播对应内容。
- 自动指标误报而确有有效变化：`decision=meaningful_change_verified`，说明具体变化及证据。
- 只有字幕变化、卡片早已摆齐、长段无解释性变化：`status=failed`，重排或重做该段。**不得用“需要听口播”这种空泛原因给所有停顿盖章。**

扫描可能漏掉：缓慢摄像机运动、装饰晃动、噪声、频繁切页或未被 ROI 排除的字幕可抬高差值。扫描也可能误报局部小动作。报告的 `quality_assessed=false` 永远保留，分数高也不代表“高级”。`audit_motion.py` 继续检查动作计划的时间与证据采样点，不能替代本门禁。

## 5. 返工与交付条件

以下情况为阻塞项：主论点没有可见状态变化；本来要求连续对象却靠整页换卡代替；未解释的长静止只换字幕；语义触发明显错位；重要文字遮挡；已知漏句/重复/错词；正式片关键检查未执行；证据属于旧版视频。

返工先修相关段落，保留旧版，再渲染受影响接点与最终文件。按实际任务优先做最多两轮质量修复；仍失败则交付**明确标记的未通过预览/部分结果**并说明问题，不能称正式成片通过。不以无意义漂浮、整片加速、缩短必要阅读或降低检测阈值来消除警告。

```sh
python "$SKILL_DIR/scripts/check_acceptance.py" work/qa/acceptance.json \
  --output work/qa/acceptance-result.json
```

退出码 0 表示记录中的必需检查通过且证据文件/哈希匹配；1 表示未完成或失败，禁止称为验收通过的正式成片；2 表示格式/文件错误。该工具不判断检查者是否诚实、不识别画面语义、不替代审美判断。仍须执行前述实际检查，不能为了 exit 0 编造 `passed`。

正式交付附简短检查说明，区分视觉、语义、技术、ASR 和听感。原始声音、密钥、私有配置不随公开发布包或技能包交付。

## v4 编辑式验收扩展（不能用旧 v3 通过结果替代）

选择 editorial-v4 路线时，复制 `assets/acceptance/record.editorial-v4.template.json` 和 `visual-plan.template.json` 到项目工作目录。占位内容默认不能通过。保持旧 schema 1 供原项目兼容，但本路线运行：

```
python scripts/check_visual_plan.py /project/visual-plan.json
python scripts/check_acceptance.py /project/acceptance.json --require-profile editorial-v4
```

schema 2/profile editorial-v4 追加：
- `art_direction`：已观察关键帧的构图层级/材质/可读性/内容适配证据；每镜必须绑定实际图片SHA。
- `transition_visual`：实际边界播放审阅，与 visual-plan 中每对前后场景一致；transition_reviews每项有from/to/effect,start/end,reviewer,具体notes及before/middle/after证据SHA。
- `visual_plan`：文件SHA。运行 checker 时读取实际文件验证，不能只说“计划已完成”。
- 图表明确source与illustrative布尔值；所有外来素材记录来源/权利/目的和SHA。全是原创代码图形可以assets空数组。
- 保留旧 final_visual/semantic/technical、声音字幕与低变化片段审阅。合理阅读停留可以解释后通过；纯装饰运动无法替代语义状态变化。

边界证据需来源于当前最终片；检查器只能匹配哈希与记录，不会自动发现截图是否来自该片，也不会自动打美学分。审阅者有责任实际提取和观看，不得制造passed。中途重渲后重新绑定成片与证据。
