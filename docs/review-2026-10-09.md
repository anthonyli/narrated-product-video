## 当前源码中的确定问题

### 1. 入口、参考文档与模板默认值不一致

`SKILL.md:18` 要求明亮且全屏录屏。`references/motion.md:7` 推荐人物与卡片分栏，示例也用半宽视频。

`assets/remotion/src/index.jsx:11` 的横版默认视频框宽度是画布的 50%；`:134` 的主背景为深色渐变。改入口文字不会改变渲染默认值。人物口播和屏幕操作需要各自适用的布局策略。

### 2. 通用能力混入个人配置

`SKILL.md:18-20`、`:29` 包含系列名称、吉祥物、颜色与结尾样式。它们对原作者有用，但不能自动成为其他用户的品牌规范。`:36` 对另一项已安装技能的依赖也没有给目标环境缺失时的路径。

公共制作原则、可选风格预设、用户私有配置是三个不同维护对象。私人音色配置位于技能外，是值得保留的隔离方式。

后续路径调整：私有配置与素材已统一放到当前制作项目的 `private/voice/`，使用配置文件相对路径；继续与技能安装目录及可发布文件隔离，不再依赖个人主目录。Git 忽略整个 `private/`。

### 3. 原比例与交付比例缺少完整接口

`assets/remotion/render.mjs:16`、`src/index.jsx:5` 和 `scripts/render_video.py:12` 仅支持 16:9、4:3、3:4。遇到用户要求保持 1660×1080 等原始尺寸时，需要临时改模板，默认 contain 也不能同时保证铺满画面和不裁切。

本次读取近期封面 PNG 头部，横版为 1672×941：`1672*9 != 941*16`。偏差很小，但它不能作为严格 16:9 验收通过。部分历史交付已明确披露此偏差，不能称为全部隐瞒。反复为这类小偏差提问，也说明导出规格与工具能力需要提前协调。

### 4. 渲染预检不核对媒体实际时长

`assets/remotion/render.mjs:18` 只要求声明时长为正数；`:79-89` 只验证文件存在。

本次实测：1 秒合成 WAV、JSON 声明 6 秒、无字幕和叠层，执行 `--validate-only` 返回 0，输出 `Timeline and local assets validated`。它确实完成了结构预检，但没有完成媒体时长验收。问题不在于已有后期解码规则完全不存在，而在于关键规则仍需要 Agent 临时拼接检查。

### 5. 保留旧版本的规则没有统一实现

`SKILL.md:68` 要求保留旧版本。Remotion 渲染器与录屏剪辑脚本会拒绝覆盖；`scripts/audio_timing.py:99` 使用 FFmpeg `-y`，`:108` 直接写映射。

本次在临时目录放置已有输出，再执行音频处理，命令返回 0，旧输出被替换。`scripts/render_video.py:58` 同样启用覆盖。这是不同路径间真实的行为差异。

### 6. 最近成功做法未完整成为可复用接口

近期制作使用过本地配音、ASR、声音柔化、多素材前后对比和动态遮罩等任务脚本。现有公共目录只有百炼服务适配及基础渲染工具。历史成片成功不能自动证明下载该目录即可复现同样的流程。

字幕脚本能明确阻止原稿与识别文本不一致，并标明逐字时间来自插值，这是正确边界。它主要接受特定的嵌套识别结果结构，接入不同本地识别器仍需适配。

### 7. 语速与完整交付需要更清晰的执行约束

生成配音默认 1.12 倍速，而近期声音修订最终按本人录音节奏取消提速。提速可改善部分冗长配音，却不是自然声音的统一解法；当前任务明确要求应优先。

技能列出 MP4、音轨、SRT、封面、标题和描述，但尚无统一交付清单检查器。此前漏交标题和描述，不能仅靠在提示词末尾重复清单解决。

## 首版定位决定的分歧

支持尽早开源：现有脚本与真实制作经验已经具有复用价值，技术型使用者能够配置依赖、提供素材并参与修订；公开有限能力可以获得真实反馈。

反对直接作为成熟工具发布：现在的稳定结果仍依靠 Agent、个人偏好、私有环境和任务补丁共同完成。普通用户若期待一句话稳定出片，会首先遇到安装、声音后端、比例、验收与返工问题。

关键变量是首批用户的操作能力与期望的自动化程度。面向会使用 Agent 的创作者，可以发布范围明确的制作技能；面向普通用户，则需要更完整的运行入口、配置、自检和失败恢复。这一定位尚待确定。
