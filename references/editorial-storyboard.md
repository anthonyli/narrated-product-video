# 从论点到可见状态的分镜

知识解说型 MG 动画先用本契约规划内容，视觉语言见 [editorial-explainer.md](editorial-explainer.md)，渲染接口见 [motion.md](motion.md)。目标是让不同主题都能得到可检查的制作过程，质量仍依赖资料、叙述判断和实际评审。

## 先确定要解释什么

从用户请求提取受众、他们已有的知识、看完应理解或能完成的事、使用场景、已确认的风格与交付要求。使用已有上下文，不重复提问。没有用户必须决定的缺失项时，记录合理假设并继续。

围绕真实问题选择叙述结构，而不固定套用“痛点 → 产品 → 功能列表 → 关注”。例如，选择题需要比较依据，原理题需要因果推导，教程需要操作与反馈，新概念需要定义与具体例子。先为主要论点找到可用证据或明确示意范围，再写完整口播；无法被素材支持的主张要调整。

分镜单位是一段有完整解释任务的内容，不是字幕行。保留同一对象的持续变化可以比频繁切页更清楚；页数和时长由信息与最终声音决定。

## 制作记录契约

在任务私有工作目录保存 `storyboard.md` 或等价结构化记录。以下是制作记录字段，**不是 `motion.json` 的渲染 schema**。选择足够明确、便于核对的表达即可，不要求机械填写冗余文案。

| 记录项 | 应能回答的问题 |
| --- | --- |
| 场景标识与口播范围 | 这段解释哪一句或哪组论点？最终时间段在哪里？ |
| 论点与观众疑问 | 看完需要理解什么？为什么此时需要解释它？ |
| 证据及边界 | 哪个文件、片段、数据或来源支持该主张？哪些只是示意？ |
| 画面主体与结构 | 观众看谁？为何用比较、流程、图表、演示或其他组织方式？ |
| 可见状态与变化 | 初始画面是什么？改变哪个对象或关系？结束时能看到什么？ |
| 声音触发点 | 哪个词或语义触发入场、强调或变化？获得最终词时间后如何对应？ |
| 素材与实现映射 | 使用哪些文件、哪些已支持字段或必要扩展？素材缺口怎样处理？ |
| 验收预期 | 在哪些时间点，应该观察到什么，才能判断本段解释成立？ |

“画面更丰富”“弹出功能卡”“高级感”不能独立充当可见状态。描述应具体到对象及其属性、位置、内容或连接的变化。静态论点可以保持稳定，但应有承担解释的图形或材料；无需为了满足格式虚构动作。

例如，一个操作论点的分镜应记录“选中原对象 → 属性改变 → 修改后的结果”，并列出素材里确实存在的状态。一个因果论点则记录“已知条件 → 关系形成 → 结果”，标清它是原理示意还是实际测量。两者不应仅替换同一卡片模板里的名词。

## 从分镜到时间轴

1. **检查语义与素材。** 先读完整分镜：每个关键主张有支持方式，主要对象可见，逻辑关系可解释。缺证据时补充授权素材、缩小主张或明确示意；空白浏览器占位不能当作已完成的产品镜头。
2. **完成口播与对齐。** 先生成连续声音，处理节奏，再取得最终时间映射；把口播范围回填为最终时间。规划时的估算时长保留为估算，不能冒充精确对齐。
3. **选择实际实现。** 根据解释任务使用当前渲染器支持的场景或基础组件。不要把本记录中的字段直接塞进 JSON；对照当前接口，执行验证，并查看实际画面。
4. **制作短样片。** 选择能暴露主要风险的代表性段落，例如复杂关系、真正的状态改变或密集界面。样片覆盖所选语义的完整变化和必要阅读时间，不固定秒数，也不只用一个简单开场证明全部可行。
5. **自行评审后扩展。** 按下表检查样片，修复会影响全片的布局或解释问题，再制作全片。只在缺少无法推断的用户选择或必要材料时提问；普通制作与检查不需要逐关批准。

## 质量检查与证据等级

在 `quality-review.md` 或等价记录中写出检查对象、时间点、观察结果、通过／未通过／未验证、修复动作与剩余问题。通过依据是实际观察，不是字段齐全或总分够高。

| 检查维度 | 检查方法与通过依据 | 不能据此声称 |
| --- | --- | --- |
| 事实与素材 | 主张与来源对应；数据口径、截图状态和示意标签符合实际 | 有来源链接就证明产品实测成功 |
| 静态画面 | 看主体稳定帧、密集处及目标比例：焦点明确、文字可读、关系清楚、字幕不遮挡 | 单张截图证明动画自然或声画同步 |
| 运动过程 | 播放或检查连续帧：对象、关系或结果按分镜改变，阅读有停稳时间，转场无突跳 | 多个间隔截图证明全部动作流畅 |
| 声音与语义 | 带声音审看关键变化和接点：动作对应所讲内容，字幕时间合理，发音与衔接可接受 | 静音检测或词时间文件证明听感自然 |
| 文件与完整性 | 完整解码、媒体参数、时长、素材和字幕覆盖符合交付要求 | 编码成功证明内容、审美或事实质量通过 |

对“操作演示”尤其检查说到动作时主体是否真的变化。标题或卡片入场本身不能替代被解释对象的变化。对“比较”检查维度与条件；对“流程”检查连接的意义；对“数据”检查比例、单位与来源。

当评审能力或素材不可用时，明确记录相应维度未验证，并保留可以复查的文件和时间点。不要让代理自写一个“通过”字段就作为质量证据；使用脚本或另一位评审者时，同样检查它实际观察了什么。

## 有限修复与交付

首次评审后，针对本次任务中最影响理解的问题修复并重新渲染，最多进行两轮质量修复。每轮记录改动及实渲复查结果；样片与全片共用这份记录，不在每个新阶段重新开启无限循环。两轮后仍未达标时停止以“自动优化”重复尝试，把结果标成草稿或部分完成，列出未通过项和具体影响。缺失关键素材或事实错误不得改标通过。

修复优先解决主张没有证据、画面未发生所述变化、读不清、遮挡及音画错位，再考虑装饰。修复当前问题不应无故重写已认可的旁白、品牌或其他段落。

全片渲染后，检查各场景的关键状态、复杂段落与所有接点；自动完整解码之外，还需适当的播放和听感检查。报告已验证范围与剩余限制。模板试片、真实素材成片、静态审查和带声音验收是不同结果，应分别命名。

## 换主题验证

更新可复用技能时，选取至少两个没有参与调参的主题，并让它们需要不同的解释结构；例如一项比较与一段因果过程，或一项数据解释与一段操作教程。只更换同一模板中的产品名、色彩和旁白不算跨主题验证。

从各自的原始资料和简短任务重新生成分镜及代表性片段，不提供样片旁白作为填空模板。可交给独立评审者检查，提供任务、原始素材与成品，不预告期待结论。用相同检查维度记录结果，明确哪些样本只有静态验证、哪些完成运动或带声音检查。

依据观察到的失败调整具体规则，避免把某个主题的版式、章节数、卡片数或时长提升为全局要求。通过这些样本只能支持对应范围内的复用判断，不能据此承诺任意主题自动达到同一质量。
