# 共享元素动画：连续变化与紧凑节奏

用于产品概念、机制和界面关系的动态解说，以及延续用户已认可的参考片。它是一条视觉制作路线；不要求把分镜强行转换成旧 Remotion `scenes`，也不等于静态卡片加淡入淡出。原始录屏仍按 [recorded-video.md](recorded-video.md) 处理。

## 延续参考，替换主题

先实际查看参考片和可编辑源码，记录配色、文字层级、关键对象、运动方式与段落接点。复用解释机制和视觉语言，不复用原项目的事实、品牌、旁白或固定七幕结构。已有源码优先在任务副本修改；只有成片时不能声称已恢复原动画工程。

当前用户认可的参考语言是奶白底、墨黑文字、蓝／橙角色色：同一组 UI 元素连续重排，扫描与聚焦指向对象，错峰启动动作，轻微镜头推进，共享元素迁移，形状遮罩衔接。颜色承担对象角色，避免每幕重新分配含义。默认不强加页码、固定顶栏、底部分段进度或持续微漂浮；稳定画面可以用于阅读。选择需要深色平台操作区的竖版交付时单独适配，不反向改掉已认可的横版风格。

默认 1920×1080、16:9。60–90 秒只是短解说的常用规划范围，最终时长取决于有效内容和声音，不用留白凑时长。画面保留简短标题和必要图解文字，默认不烧录口播字幕，另交口播稿；需要字幕时交独立 SRT，只有明确要求时烧录。

## 让同一对象承担解释

- **连续重排：** 给同一对象稳定标识，在初始、变化、结果状态间插值位置、尺寸、层级或颜色。先解释具体改变，不整页消失后换另一张卡。
- **扫描与聚焦：** 扫描、边界和测量指向正在解释的对象；没有检测数据时标“示意”，不制造扫描通过率或真实发现。
- **共享元素迁移：** 沿用对象外形或位置，缩放／移动进入下一关系图；切换前后能认出同一个对象。
- **遮罩转场：** 遮罩覆盖交接点时交换场景，遮罩起点跟随当前焦点；检查开口、半程、闭合与结束帧，避免露底或突然换色。
- **镜头推进：** 只用于引导注意力；文本阅读阶段保持可读，不能用轻微缩放掩盖没有信息变化的长停顿。

实际操作与概念解释分别标注。自制 UI、设计改造和规则网格是概念演绎时，应保留“概念演绎／非实测演示”等可读说明，不能仅在交付文字里免责而画面仍冒充实测。

开源介绍不默认把上述制作说明再写成结尾口播；正文与自然互动收尾保持连贯。用户本人提供的使用经历可按其陈述范围呈现，不能据此扩展为全部能力已验证；必要示意标识和事实边界不变。

## 修改“慢”和“不流畅”

先定位慢在动作启动、持续时间、尾部拖曳还是两个动作之间的空白。保持已认可的主体和构图，优先改时间线、曲线与重叠。不要整片倍速，也不要为配合动画机械加快口播。

以下是新动作的起始调参范围，按距离、语义和帧率调整，不是所有主题的硬上限。所附 v3 参考保留已实渲的较长 UI 重排和形状遮罩；它已相对 v2 缩短，不能为满足单个阈值破坏连续解释：

| 动作 | 建议时间 | 衔接 |
| --- | --- | --- |
| 短入场／聚焦 | 0.18–0.32 秒 | 快启动、短收尾；文字先进入可读状态 |
| 页面／形状遮罩转场 | 0.18–0.30 秒 | 尽量不超过 0.35 秒；无额外空白帧 |
| 有解释任务的 UI 重排 | 0.35–0.65 秒 | 同一对象连续运动，落点清楚 |
| 相邻元素错峰 | 0.04–0.08 秒 | 下一对象在前一动作结束前启动，不累计成串行等待 |
| 阅读／口播停稳 | 按实际内容 | 在分镜里记录阅读或语义原因，不加固定尾停 |

普通进场可用快速 ease-out，迁移可用短 ease-in-out；避免每个对象均从静止慢起步、长弹簧收敛和夸张回弹。动作重叠要保持因果：前一状态尚未读懂时不抢切，但下一场无需等待所有装饰动作结束。保持对象运动方向和落点连续；帧率提高不能修复时间线停顿。

声音采用 [local-tts.md](local-tts.md) 的项目私有本人声音入口。音轨完成后按实际语义触发点调整画面，不能将旧静音样片的时间分配直接当作配音对齐。只改动画流畅度时保留已有音轨和语速；必须改稿或处理音频时另生成时间映射。

## 可运行渲染入口

复制整个 `assets/shared-motion/` 到制作任务目录，按其中 [README](../assets/shared-motion/README.md) 运行。需要现存 Python 3.10+、Pillow、本地中文字体和带 libx264 的 FFmpeg；脚本不安装或下载依赖。可用 `VIDEO_FONT_REGULAR`、`VIDEO_FONT_BOLD` 指定有使用权限的字体，`--ffmpeg` 或 `FFMPEG_BIN` 指定编码器。

```sh
# 在复制后的 shared-motion 目录执行；输出必须使用新文件名。
python render.py examples/impeccable-v3.json outputs/state.png --preview-at 6
python render.py examples/impeccable-v3.json outputs/junction.mp4 --start 5 --end 8
python render.py examples/impeccable-v3.json outputs/visual.mp4
python render.py episode.json outputs/voiced.mp4 --audio ../voice/narration.wav --validate-only
python render.py episode.json outputs/voiced.mp4 --audio ../voice/narration.wav
```

`--audio` 接收完整连续 PCM WAV，实测长度必须与完整场景总长相差不超过一帧；不自动倍速、补静音或硬塞时间。`--start`／`--end` 用于明确截取片段；`--fps 30` 只减少采样帧率，不改变动作时序。无音轨时输出无声视觉样片，无烧录口播字幕。

配置的 `adapter` 是相对本地路径；其 `create_scenes(config, config_dir)` 返回 `Scene(id, duration, frame, holds, rests)`。**这是可信 Python 源码执行接口，包含 `--validate-only` 在内都会导入适配器；先审阅代码，不把陌生 JSON 当作纯数据验证。** `frame(source_time)` 返回对应画布的 Pillow 图像，所有帧按确定时间计算。配音、声音样本和密钥不属于适配器。

参考 `editorial_ui.py` 保留已提供 v3 的几何和动作，本期文案、界面文字、命令、规则数和来源放在 `examples/impeccable-v3.json`；其中四行命令、两份文档、三处聚焦是这个适配器的布局限制，不是通用叙事规则。`examples/flow-comparison.json` 及其适配器展示另一种共享对象路线比较。讲新的因果机制时另写符合该接口的场景，不通过替换项目名强套本期结构。下一期重新核实事实，不沿用示例的日期、数字或许可证结论。

每个场景可通过 `holds` 在稳定源时间点插入有原因的停稳，通过 `rests` 缩短人工确认的阅读区间；区间外的动作仍按原时序运行。例如：

```json
{
  "id": "context", "source": "context",
  "rests": [{"start": 4.7, "end": 6.2, "duration": 0.8,
             "reason": "这一段口播已结束，缩短文档停留"}],
  "holds": [{"at": 6.25, "duration": 0.3,
             "reason": "等待当前语义收束再启动遮罩"}]
}
```

源时间始终指原场景，不随前面的调整改变。不要选入场、重排、聚焦移动或遮罩本身作为 `rests`；其中环境微动会随阅读区间重映射，需检查新接点。`holds` 冻结该帧，不适合仍需连续运动的状态。先按实际语义确定章节边界，再调整这些停留，而非按旧样片秒数截断口播。

## 用户要求烧录字幕时

当次明确要求优先于本路线无烧录字幕默认值。先用真实本地词时间戳对齐正式口播稿，并记录同音识别修正和仍待审听的读音；真实漏词、重复或错读需修复音频，不能仅改字幕掩盖。修改音频后更新后续时间戳和画面停留。

```sh
python <skill-dir>/scripts/render_captions.py \
  --video outputs/clean.mp4 --captions work/captions.json \
  --output outputs/subtitled.mp4 --srt outputs/subtitled.srt
```

字幕文件沿用 `{"captions":[{"start":0,"end":1,"text":"示例"}]}`，时间以最终音轨秒数为准。此后处理直接覆盖全幅画面，不缩放、裁切或补边，音轨直接复制。场景本身需给字幕留安全区；不能为了字幕缩小整个画面而产生左右和底部粗边。

1080p 字幕沿用原 `assets/remotion/src/index.jsx` 的 `Captions` 样式：`PingFang SC` 40px、约600字重、60px行距，浅字 `#fdfaf3` 配深色圆角盒 `#17120aee`，内边距上下14px／左右28px、圆角12px、底距76px。最多两行，按当前短句内容确定盒宽；不铺整条底带，不增加弹跳。ASS用独立矢量背景层和每行文本层保持圆角与行距。未提供真实强调词时间时显示普通字幕，不伪造逐字高亮。

可用 `--font-name` 指定已安装字体；`--font-file` 指定与名称匹配的本地字体文件时，用现有 Pillow 测宽并让 libass 加载同一文件。未提供文件时按全角／半角保守估计，仍需抽帧检查字体回退、实际盒宽和内容遮挡；验证命令不证明字体或排版已通过。依赖现存带 libass 的 FFmpeg，可用 `--ffmpeg` 或 `FFMPEG_BIN` 指定。先 `--validate-only`，再检查长句、明暗背景、转场及片尾。背景应全幅延展，UI安全区在场景内部安排。当前 `editorial_ui.py` 可用 `caption_safe: true` 调整内容资产，不缩放整幅画布；本次单行字幕盒占 y916–1004，改为两行时必须另检查 y856–1004。

需要互动收尾时，在结论之后追加 `source: "engagement"` 场景，以实际口播设置 `duration`；`content.engagement` 提供两行 `lines` 与三项 `actions`。沿原技能示例“有想法欢迎留言，觉得有用记得点赞、关注。”完成声音、字幕和画面，使用当前视频的配色与短缓动。

`--mode burn` 烧录并交独立SRT；`--mode sidecar` 保留原画面，只输出视频副本和独立SRT。任务制作记录中的 `subtitles.enabled`／`mode` 表达当次选择，由制作流程据此调用后处理脚本；共享元素核心 `render.py` 本身不读取这一块，也不自动烧录。保留无字幕原版，不覆盖已有交付。

## 可检查的节奏记录

在任务 `work/<task>/motion-plan.json` 记录主要动作和有意义停稳，运行 `scripts/audit_motion.py`。这个文件是 QA 记录，不是任何渲染器的输入 schema，也不替代源码里的真实时间轴。时间必须从实际实现导出或逐项核实，不能为了通过审计随意填写。

```json
{
  "duration": 4,
  "fps": 30,
  "actions": [
    {"id": "layout-change", "kind": "reflow", "start": 0, "end": 0.55},
    {"id": "next-view", "kind": "transition", "start": 3.72, "end": 4}
  ],
  "holds": [
    {"start": 0.55, "end": 3.72, "reason": "阅读改变后的布局；对应这一句完整解释"}
  ]
}
```

```sh
python <skill-dir>/scripts/audit_motion.py work/<task>/motion-plan.json
```

审计提示慢转场、过长入场／聚焦／离场和未解释的停顿，并为所有主要动作给出边界抽帧点。`camera` 微动不抵消长停顿。警告可因解释需要而保留，但须实际审看后记录原因；`qualityAssessed: false` 表示脚本没有判断视觉质量。

## 实渲验收

先渲染一个包含真实重排与跨场交接的短片段，检查首尾状态与连续过程，再渲染全片。保留原版和调整版，按正常播放速度比较所有接点：慢起步是否缩短、可读落点是否保留、相邻动作是否衔接、遮罩是否露底、共享元素是否跳位、最后一帧是否完整。

静态抽帧检查文字、层级与示意标签；连续帧或播放检查过程；带声音审看检查语义触发和听感。这三类证据分别记录。完整解码、尺寸／帧数／时长、音画同步和峰值检查通过后，交付 MP4、可编辑源、独立口播稿与音轨（如有）；不要把“脚本运行成功”写成“视觉与声音全部验收通过”。

新主题验证选择不同解释结构，例如对象关系与状态比较，而不是只给参考片换产品名。缺少参考源码、真实素材或可用声音时先完成独立部分，准确报告缺项，不伪称已集成或已合成。
